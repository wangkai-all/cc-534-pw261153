# 包装线：交班次表 × 标签识别结果归集（本地演示）

从零实现的本地小应用，**只使用 Node.js 内置模块**，无第三方依赖。识别结果全部由
`data/sample-import.json` 手工给定，不接任何真实识别服务。

## 启动

```bash
node server.js          # 默认端口 3000
PORT=8080 node server.js # 读取 PORT 环境变量，始终绑定 127.0.0.1
```

打开 http://127.0.0.1:3000 。

## 测试

```bash
node --test
```

共 25 个用例（`test/domain.test.js` 纯领域逻辑、`test/http.test.js` HTTP 端到端），
覆盖题面中的正常与异常结果。

## 业务规则

1. **导入标签识别样本**：一次同时提交交班次表与标签识别结果。每箱以原图编号
   `imageId` 唯一标识；置信度 `>= 0.8` 自动确认入账，`< 0.8` 保留原图编号与候选批号，
   进入待人工确认状态。
2. **确认一条改号**：人工把某张原图确认/修正到正确批号。系统只移动这张原图已认领的
   1 箱，**绝不重新添一箱**（箱总数恒定，且同一原图不会同时归属两个批号）。
3. **对照批号归集**：按批号汇总实际箱数，与交班次表的计划箱数对照，给出
   相符（matched）/短少（short）/超出（over）/班次表无此批号（unknown-batch）。

### 低置信度的两种处理模式（页面可切换，读数的人始终能看到当前状态）

| 模式 | 待确认箱处理 | 改号时 | 状态标识 |
| --- | --- | --- | --- |
| 先等确认再入账 (`confirm-first`) | 不计入任何批号 | 直接认领，无冲正 | `awaiting-confirmation` → `final-confirmed` |
| 先记暂定量再冲正 (`provisional`) | 按候选批号先记暂定量（页面标「暂记」） | 红冲原批号 −1、蓝补新批号 +1 | `provisional-open` → `final-reversed` |

两种模式在全部确认后的最终归集结果一致，差异只在中间状态与是否产生冲正分录。

## 页面操作与核对

页面提供三个业务操作：**导入标签识别样本**、**确认一条改号**、**对照批号归集**
（另有重置与模式切换）。所有数字都由后端实际处理返回，不是前端写死的。

业务结果区 `#result` 带有 **`data-evidence-result`** 属性，值为去掉时间戳的稳定 JSON
快照（每箱状态、各批号箱数/差异/原图清单、暂记箱、冲正分录、合计），可直接用于核对
操作前后的内容变化。

## 目录结构

```
server.js               HTTP 服务（http/fs/path/url 内置模块，绑 127.0.0.1）
lib/domain.js           纯业务逻辑：校验、导入、确认改号、归集、冲正、evidence 快照
data/sample-import.json 手工给定的合成样本（含低置信度与一条误识改号场景）
public/index.html       单文件页面（原生 HTML/CSS/JS）
test/domain.test.js     领域逻辑用例（正常 + 异常）
test/http.test.js       HTTP 端到端用例（含 400/403/404/409 异常）
```

## 合成样本场景

6 箱 / 3 个批号（A01=2、A02=3、B01）：

- IMG-001~003：高置信度自动确认；
- IMG-004（0.62）、IMG-006（0.71）：低置信度，人工确认维持候选批号；
- IMG-005（0.55）：喷码粘连误识为 B01，实际是 A02，人工改号——
  暂定量模式下可看到 `红冲 B01 −1 / 蓝补 A02 +1` 的冲正移动，箱总数始终为 6。
